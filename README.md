## 2. 아키텍처 — 왜 이렇게 설계했나

### 2.1 싱글톤을 하나로 제한한 이유

(GameManager만 싱글톤으로 두고 나머지 시스템은 이벤트로 통신하게 한 이유를 여기에 적기.
 "매니저마다 싱글톤을 두면 서로 직접 참조하게 되어 결합도가 올라가고, 초기화 순서 의존이 생긴다"는
 논지를 본인 언어로. 실제로 겪은 문제가 있었다면 그게 가장 좋은 근거)

### 2.2 입력 레이어 추상화

(Input System의 Action 기반으로 입력을 추상화한 이유.
 향후 플랫폼 확장 시 UI 레이어만 교체하면 되는 구조라는 점)

### 2.3 동반자 AI의 책임 분리

(NavMeshAgent에 맡긴 부분 = 경로 탐색/이동
 직접 설계한 부분 = 언제 따라가고 언제 멈추고 무엇에 반응할지 판단하는 상태머신
 이 구분을 명확히 쓰는 것이 이 README에서 가장 중요한 문단)
